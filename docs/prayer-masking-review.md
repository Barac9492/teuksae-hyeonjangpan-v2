# 기도문 별도 검토와 가림 게시

상태: 사용자 직접 승인 후 운영 DB 적용 완료. 앱 PR·CI·배포 진행 중.
기준 main: `42cdee70891df83977ed7ae9e070cd8100437310`.

## 승인된 사전

승인된 표현: **자살, 강간, 폭행, 자해, 극단적 선택, 성폭행, 성폭력, 강제추행, 살인, 살해**.
전체 10개. 일반적인 질환·건강·신체·정체성 표현은 추가하지 않았다.
`server/prayer-masking.js`의 버전 관리되는 목록이 설정 지점이다. 목록 변경 시 일치하는 새 SQL 마이그레이션도 필요하다. 자동 동의어 확장, 외부 AI, 위험도 추정, 문장 재작성은 없다.

정확한 연속 문자열을 모두 `**`로 바꾸고, 같은 위치에서는 긴 표현부터 처리한다. `성폭행`은 `성**`가 아닌 `**`다. 멱등적이다. `자살예방`과 `살인미소` 같은 합성어도 각각 `**예방`, `**미소`가 된다. 문맥 오탐을 자동 판단하지 않으며 관리자는 게시·보류·휴지통을 선택한다. 가림 단어를 임의로 복원하거나 문장을 편집하는 기능은 없다.

한글 정규화나 공백 정리는 하지 않는다. NFD 자모, `자 살`, `자\n살`, 제로폭 문자, `극단적  선택`은 매칭하지 않는다. 모든 민감 표현을 포괄한다고 주장하지 않는다. 현재 범위는 `kind='prayer'`뿐이며 묵상·사진 메모·사진 픽셀은 대상이 아니다.

## 흐름과 보안 경계

- 원문 접수 → 기존 동의·pending 상태·원문 기반 재시도 해시 유지.
- 지정 표현 발견 → 일반 검토에서 제외 → **별도 검토 · 가림 게시**.
- 관리자에게 작성 원문(일치 표현 강조), 정확한 공개 표시, 별도 확인 버튼 제공.
- **가림 처리본 게시 → 확인 후 가림 처리본 게시** 한 건씩 처리.
- 서버와 DB 모두 일반 승인 우회를 차단한다. DB의 기존 세션 검증·행 잠금 안에서 `expectedVersion`, 사전 버전, 제시된 공개 문자열을 다시 확인한다. 임의 문구·오래된 미리보기는 거절한다.
- DB 원문과 `masked_public_text`, `masked_policy_version`, `masked_source_hash`를 분리한다. 원문 해시는 변경 감지 용도이며 보안 토큰이 아니다.
- 공개 RPC는 승인·ready 조건에 더해 유효한 검토 여부를 확인하고, 검토한 공개 문자열만 반환한다. 제외 조건은 페이지 LIMIT 이전에 적용한다. 페이지 API와 옛 `list` RPC 모두 동일하다.
- HTTP 공개 응답은 필드 허용 목록을 사용해 원문/검토 메타데이터를 제거한다. 서버와 DB 정책이 다르면 기도 항목을 공개하지 않으며 게시 동작도 차단한다. 구버전/장애 시 원문 fallback이 없다.
- 관리자 원문·감사기록은 기존 superadmin 경계에 남는다. 감사 기록에는 `masked_approved` 결정과 사전 버전 및 기존 세션 귀속 정보를 남긴다.
- 작성자 개인 입력·원문 미리보기·PNG 저장은 원문을 유지한다. 제출 기록은 공개 보류 상태를 정확히 표시한다. 철회·삭제는 원문과 파생 공개 문자열을 함께 지운다. 휴지통 복원은 기존 가림 승인을 재사용하지 않는다.

작성 안내:
> 어린이도 함께 보는 공간입니다. 일부 표현은 관리자가 확인한 뒤 **로 가려 공개합니다. 원문은 보관됩니다.

## 이미 승인된 글과 정책 변경

기존 승인 글 중 새 사전에 해당하는 글은 원문이나 상태를 일괄 수정하지 않고 공개 조회에서 제외한다. 관리자 별도 검토에 `공개 보류 · 가림 재검토 필요`로 나타난다. 재승인 전까지 새 가림본도 공개하지 않는다. 관련 표현이 없는 기존 승인 글은 유지된다.

기존 가림 게시의 사전 버전이 바뀌면 재검토 전까지 보류한다. 단어를 사전에서 제거해도 자동으로 원문이 노출되지 않는다. 바뀐 미리보기를 명시적으로 확인해야 한다. 원문이 바뀌어도 기존 확인은 무효다. 일반 목록·승인 필터는 보류 항목을 공개 중이라고 표시하지 않는다.

API no-store, SW의 API 캐시 제외, 공개 본문의 메모리 전용 보관을 유지한다. 이미 열린 탭·배포 전 진행 중 응답·외부 사본은 소급 회수할 수 없다. 기존 전경 30초 갱신, 숨김·오프라인·실패 시 목록 제거가 다음 서버 응답으로 전환한다. 배포 순간 모든 기존 화면에서 즉시 제거된다는 보장은 하지 않는다.

## 로컬 마이그레이션과 배포 제안

`20261004152334_reviewed_prayer_masking.sql`: 게시물에 nullable 컬럼 3개, 감사 기록에 nullable 사전 버전 컬럼 1개, 내부 정책 함수와 기존 RPC 교체. 기존 행 backfill·원문 수정·상태 일괄 변경 없음. 기존 테이블/RLS/역할/스토리지 권한을 확대하지 않는다. 새 내부 함수는 service_role만 실행할 수 있다.

1. 사용자에게 위 사전 10개, 기도만 적용, 기존 매칭 승인 글의 일시 공개 보류를 확인받는다. 목록 변경 시 서버 목록과 새 SQL을 함께 맞추고 합성 SQL/JS 일치 테스트를 다시 수행한다.
2. 배포 승인 후 최신 main에 재검토·통합하고, 운영 데이터 본문을 읽지 않는 스키마/함수/권한 검증으로 현재 상태를 확인한다.
3. **DB 마이그레이션 먼저**, 바로 이어 같은 정책 버전의 앱/API를 배포한다. 이 짧은 사이 기존 앱의 일반 승인은 지정 표현에서 DB가 거부하며, 별도 검토 UI가 나타날 때까지 해당 글은 보류된다. 새 서버가 구 DB를 만나도 승인 정책 확인에서 차단된다.
4. 합성/테스트 환경에서 익명 공개 목록(옛 경로·모든 페이지), 원문 접근 거부, 관리자 미리보기/확정, 철회, 캐시/오래 열린 탭 전환을 확인한다. 실제 제출 내용을 외부 서비스로 보내지 않는다.
5. 앱 롤백이 필요해도 DB 공개 보류·우회 차단은 유지한다. 구 RPC로 되돌리면 원문 공개가 재개될 수 있으므로 DB 역마이그레이션은 자동 수행하지 않는다.
