## 자동 갱신의 정확한 범위

- 공개 예배 공간·주차 현황: `/api/status`, 20초 간격. 관리자 현황 읽기도 20초.
- 공개 기도·사진·묵상 목록과 사진 참여 건수: 현재 보고 있는 페이지를 30초 간격으로 조회. 탭별 컴포넌트는 상태 보존을 위해 계속 마운트되므로 브라우저가 보이는 동안 세 공개 피드는 각각 조회된다.
- 브라우저가 숨겨지거나 오프라인이면 조회를 멈추고 진행 중 요청을 취소한다. 화면 복귀, `pageshow`, 온라인 복구 시 즉시 다시 조회한다. 같은 폴러 안에서 요청 중첩 없음. 조회 요청은 8초 제한, 실패 후 다음 주기에 재시도.
- 페이지·선택 탭·입력 중 글·동의 선택·스크롤을 초기화하지 않는다. 공개 목록 조회 실패 시 기존 카드는 남기되 최신이 아닐 수 있다는 오류를 표시하고 제출은 막는다.
- 현황 연결 실패/미입력/미래 시각/10분 초과 시 현재 이용 가능 안내를 내리지 않고 `확인 필요`로 표시한다. 마지막 현장 확인 시각과 자동 조회 시각은 다른 의미다.
- 관리자 **검수 목록**은 기존처럼 `검토 목록 새로고침` 버튼을 쓴다. 검수 도중 자동 재정렬하지 않는다. 나눔 이야기, 입력 미리보기, 기기 저장 카드 등 기기 내 기능은 다른 사용자와 동기화되지 않는다.
- 열어 둔 구버전 앱에 새 코드가 자동 주입되지는 않는다. 배포 후 한 번 새로 열거나 새로고침해야 새 UI/동작을 받는다. 이후 데이터 갱신에는 수동 새로고침이 필요 없다.

## 기도 타이머의 정확한 동작

남은 시간을 표시하는 카운트다운이다. `Date.now()` 기준으로 계산하므로 화면이 숨겨지거나 기기가 잠겨도 경과 시간은 유지되고 복귀 즉시 보정한다. 일시정지 중에는 흐르지 않는다. 앱 안의 탭/기도 메뉴 변경에도 마운트가 유지된다. 초기화하면 현재 선택한 시간으로 돌아가고 시간 변경이 가능하다. 앱을 닫거나 새로고침하면 초기화된다. 기도 본문이나 타이머 상태를 서버/브라우저 저장소에 추가 저장하지 않는다. 초 단위 화면을 스크린리더로 계속 읽지 않고 시작·정지·완료 상태를 알린다.

## 목록 확장·개인정보 경계

- `(created_at DESC, id DESC)` 커서로 동시각 게시물도 중복 없이 페이지 이동. 쿼리는 다음 페이지 판단용 13건을 읽고 최대 12건만 반환한다. 화면도 현재 12건만 렌더링하며 무한 스크롤로 누적하지 않는다.
- 승인(`approved`) 및 준비 완료(`ready`) 게시물만 반환한다. 글/행사일/공개 사진 경로 등 기존 공개 필드만 반환하며 삭제 토큰, 검수 정보, 저장소 경로는 반환하지 않는다.
- 현재 페이지를 다시 조회하므로 승인 취소/삭제는 다음 성공 조회에서 사라진다. 새 글은 최신 페이지에서 확인할 수 있다. 이전 페이지 열람 중 강제로 최신 페이지로 이동하지 않는다.
- 사진은 `loading="lazy"`, 동일 출처 `/api/community/photo` 경유. 기존 서버 사진 접근 재검증, 비공개 버킷, EXIF 제거, 동의, 검수, 소유자 삭제 절차 유지.
- 사진 참여 건수는 한국 시간 접수일의 준비 완료·검수 대기/승인 사진 **건수**이며 사람 수가 아니다. 기존 정의를 유지했다.
- 관리자 검수 목록은 기존 최대 100건과 검수 대기 우선 정책을 유지했다. 이번 변경은 공개 피드의 페이지 확장이다.

## 원격 적용 승인 범위

신규 파일: `supabase/migrations/20261003062254_church_feedback_guidance_and_pages.sql`.

1. `ops_resources.guide_floor`(1–5) 추가 및 드림센터 안내 상태/층 조합 제약. `ops_history.before_guide_floor`, `after_guide_floor`, `ops_request_receipts.guide_floor` 추가.
2. `parking.dream` 행 1개를 `checking`, 안내 층 NULL로 추가. 총 대수는 생성하거나 요구하지 않는다. `parking.calvary`, `parking.dream.b1`–`b5`, 모든 이력·영수증을 보존한다.
3. 저장 RPC를 안내 층 기본값(NULL)을 가진 7인자 버전으로 교체. 기존 5/6인자 호출은 기본값으로 호환. 버전 충돌·계정 권한 재검증·동일 요청 재시도·원자적 이력 기록을 유지한다. 공개/관리자 읽기 RPC에 안내 층을 추가한다.
4. 승인 게시물 커서용 부분 인덱스와 `community_public_page(text,timestamptz,uuid)` RPC 추가. 신규/교체 RPC 실행은 기존 방식대로 `service_role`만 가능하며 `PUBLIC`/`anon`/`authenticated` 실행 권한은 제거한다. 앱의 서버 API를 통해 승인된 공개 결과만 전달한다. 기존 RLS·계정·버킷/사진 접근 정책은 변경하지 않는다.

모두 하나의 트랜잭션이다. SQL은 **로컬 PGlite PostgreSQL에서만 실행했다**. 실제 Supabase 마이그레이션 이력·확장·함수 의존성·운영 규모의 인덱스 생성 시간은 아직 확인하지 않았다.

승인 후 권장 순서: 운영 백업/기존 002–010 적용 및 함수 시그니처 확인 → 스테이징에서 동일 SQL과 API 검사 → 운영 마이그레이션 → 서버·프런트 동시 배포 → 실제 운영 담당자가 현재 안내 층 확인/입력 → 공개 읽기와 시각 검증. 운영에 시험 기도·사진을 올리지 않는다. DB 먼저 적용하지 않으면 새 페이지 RPC는 실패하고 드림센터 통합 안내는 준비 중으로 남는다.

롤백은 데이터 삭제 대신 전진 수정이 우선이다. UI 문제면 기존 배포로 돌리되 새 통합 행을 구버전 관리자 퍼센트 입력에 노출하지 않도록 호환 읽기 필터가 필요하다. 원래 6인자 writer를 무조건 복원하면 새 안내 층/이력·영수증 계약을 잃을 수 있으므로, 신규 컬럼·행·영수증·함수는 보존하고 `parking.dream`을 읽기 결과에서 숨기는 호환 패치부터 별도 검증한다. 새 데이터를 없애는 DROP/DELETE 롤백은 준비하거나 실행하지 않았다.
