# 기도·사진 공개 접수 운영

## 공개 흐름
- 기도·사진 작성/미리보기/파일저장은 제출과 별개다. 공개 범위 동의 후 `공개 접수하기 · 검수 후 게시`를 눌러야 서버로 전송된다.
- 접수는 검수 대기. 슈퍼 어드민은 대기 중 내용과 사진을 볼 수 있다. 주차·예배 공간 계정은 검수 권한이 없다.
- `/admin` → 기도·사진 검수에서 내용을 확인하고 공개 동의 확인 체크 후 별도 승인 버튼을 누른다. 사진은 미리보기를 읽기 전 승인할 수 없다.
- 승인된 내용만 공개 기도/사진 화면에 나온다. 인터넷 누구나 볼 수 있으므로 실명, 연락처, 민감한 건강·가족 정보와 제3자/미성년자 얼굴을 확인한다. 미확인 동의나 위험한 내용은 반려한다.
- 제출자는 같은 브라우저의 `내 제출 기록`에서 상태 확인·철회할 수 있다. 브라우저에는 본문 대신 제출 ID/종류/삭제 권한만 저장한다. 브라우저 저장소를 지우면 이 권한도 사라질 수 있다.
- 반려/삭제는 본문을 지우고 사진 원본 파일을 제거한다. 이미 외부에 저장된 사본은 회수할 수 없다. 재시도 안전성을 위한 비공개 해시·상태·감사 기록은 남는다.

## 참여 건수
`오늘 사진 참여 N건`은 **한국 시간 실제 업로드 완료일 기준**이다. 중복 인원·같은 사진의 별도 접수도 각각 세며, 인원이나 출석 인증으로 표현하지 않는다. 같은 요청의 네트워크 재시도는 한 번만 센다. 업로드 미완료·반려·삭제는 제외하고 검수 대기 및 공개 상태를 포함한다. 실패/연결 오류를 0건으로 표시하지 않는다. 사진에 선택한 행사일과 오늘 집계일은 다를 수 있다.

## 저장소·권한
- Migration005는 기존 operations sessions가 있는 DB에 별도로 추가한다. 보류 중인 migration004와 무관하며 기존 예배/주차 테이블과 RPC는 바꾸지 않는다.
- 테이블 `community_v2_items`, `community_v2_rates`, `community_v2_audit`에는 RLS 및 익명/일반 로그인 직접 접근 금지를 적용한다. RPC는 service_role에만 허용한다.
- `community-photos-v2`는 비공개 PNG 전용 저장소. 서버에서 크기/CRC/이미지 디코딩 검증 후 재인코딩해 EXIF 등 메타데이터를 제거한다. 공개 이미지 API도 요청마다 승인 여부를 확인한다.
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_SESSION_SECRET`은 기존 서버 전용 설정을 사용한다. 신규 `CRON_SECRET`은 Vercel Production Secret으로 저장한다. 어떤 비밀값도 Git에 넣지 않는다.
- 기본 공개 접수 origin은 `https://teuksae-hyeonjangpan-v2.vercel.app`. 도메인을 바꾸면 `COMMUNITY_ALLOWED_ORIGIN`과 관리자 허용 origin을 명시적으로 업데이트한다.

## 자동 정리와 한도
- `/api/community/cleanup`: CRON_SECRET bearer 인증. Vercel cron 매시 17분(UTC)에 실행한다. 실패는503, 결과는 cleaned/failed 수만 반환한다.
- 삭제/반려 파일을 재확인하고 1시간 이상 미완료인 업로드를 삭제 처리한다. 늦게 도착한 파일도 다음 순회에서 정리한다. 한 번에50개, 마지막 정리 시각 순으로 순회한다.
- PNG 바이너리 최대3MB, 최대400만 화소. 디코딩 전에 IP별 요청 시도 제한240/분, 새 접수는 같은IP에서 사진60/분·기도120/분. 공용 Wi-Fi 사용을 고려한 한도이며 제한 시 잠시 기다렸다 재시도한다. 원시 IP는 저장하지 않고 서버 비밀키를 사용한 해시만 저장한다.
- 일반적인 게시물 보관 종료는 자동 설정하지 않았다. 행사 후 공개 지속 여부를 운영자가 결정하고 필요 시 반려/삭제한다. migration 헤더의11/10 전체 정리는 운영 검토일 제안이며 자동 실행되는 약속이 아니다. 전체 정리가 필요하면 반드시 Storage API로 파일을 먼저 지우고 관련 테이블을 정리한다.

## 검증
2026-09-28 실제 Supabase에서 전체 마이그레이션과 권한/중복재시도/미승인 비공개/사진수/승인/삭제 검증을 한 트랜잭션 안에서 실행하고 ROLLBACK했다. 이후 승인된 신규005만 적용했다. 저장소 public=false 및 anon RPC 실행권한 false를 확인했다. 테스트 관리자 계정·테스트 공개 게시물은 롤백되어 남지 않았다.

## 묵상 전체 공개 옵션 (2026-09-28)
- 기도 → 특새 묵상: 날짜별 개인 작성과 파일 저장은 그대로 유지한다. 특정인 공유 메뉴 대신 전체 공개 동의·접수를 선택할 수 있다.
- migration006은 기존 접수 데이터를 유지하며 reflection 유형과 최대1000자 제약을 추가한다. 서버 접수·검수·승인·철회는 기도와 동일하다.
- 승인된 묵상은 로그인 없이 모두가 묵상 화면에서 볼 수 있고 행사 날짜를 표시한다. 관리자 검수 목록에서도 묵상으로 구분한다. 사진 참여 건수에는 포함하지 않는다.
