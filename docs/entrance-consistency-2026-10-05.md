# 출입 안내 일관성 수정

이 문서의 10분 후 값 숨김 설명은 후속 승인된 [마지막 운영 현황 유지](status-retention-2026-10-05.md) 정책으로 대체됩니다.

관리자가 저장한 값이 HOME에서 다른 문구로 보이는 이유를 드러내고, 서로 충돌하는 입장 안내를 저장하기 전에 확인할 수 있도록 했습니다.

- HOME 현황에 마지막 확인 시각(한국 시간)을 표시합니다. 날짜가 다르면 날짜도 표시합니다. 10분이 지난 값은 계속 ‘확인 필요’이며 ‘10분 경과’를 덧붙입니다. 미입력·비정상·미래 시각은 확인 기록이 있다고 주장하지 않습니다.
- HOME의 ‘학교 출입’을 ‘송림 입장 단계’로 바꿨습니다. 교문·체육관·본당의 진행 단계를 뜻하는 항목임을 구분합니다.
- 관리자의 ‘공개 상태’와 저장 후 안내는 기존 servicePeriod를 공유합니다. 10월 5–10일 04:40–05:50에는 ‘예배 중’, 05:50 이후 공간 항목은 ‘예배 후 · 귀가 안내 표시’입니다. 주차는 05:50 이후 현황 표시를 재개합니다. 20초 반영 안내는 실제 조회가 허용되는 시간에만 나옵니다.
- 저장 전 서버에서 출입 단계·본당·체육관의 최신 저장값을 읽고 선택한 값과 비교합니다. 충돌 시 담당자는 돌아가 수정하거나 순차 갱신 중임을 확인해 해당 항목만 저장할 수 있습니다. 다른 항목은 자동 변경하지 않습니다. 기존 저장값 차이는 읽기 전용 현황판에서도 보입니다.
- 확인 중 취소·탭 이동은 저장하지 않습니다. 다른 항목의 버전이 바뀌면 재확인을 요구하고, 저장 대상 버전이 바뀌면 기존 충돌 비교 절차를 사용합니다. 중복 클릭은 하나의 저장으로 처리하며 기존 requestId/expectedVersion을 유지합니다. 최신 조회 실패 시 저장하지 않습니다.

## 경고 범위

확인 전(checking)은 개방 여부를 단정하지 않습니다. 교문 개방 전/교문 개방 단계에서 본당 또는 체육관이 available/busy/full이면 단계가 뒤처진 것으로 안내합니다. 체육관 먼저 개방 단계에서 체육관 closed, 또는 본당 available/busy/full이면 안내합니다. 본당 입장 중 단계에서 본당 closed/full, 본당 입장 마감 단계에서 본당 available/busy이면 안내합니다. 본당 단계로 체육관 상태까지 추론하지 않습니다.

이는 마지막 저장값 간 차이에 대한 안내이며, 현장 상태를 자동 판정하거나 관련 항목을 묶어 저장하는 규칙이 아닙니다. 서버의 저장 대상 버전 충돌 방지는 기존대로 유지합니다. 관련 항목이 사전 조회 직후에 바뀌는 경우까지 원자적으로 잠그지는 않습니다.

## 출시 제안

프런트엔드만 변경하며 DB 마이그레이션이나 운영 데이터 보정은 필요 없습니다. 배포 승인 후 최신 main에 이 커밋을 반영하고 앱을 배포한 다음, 공개 HOME의 확인 시각과 관리자 공개 상태 문구를 읽기 전용으로 확인하면 됩니다. 실제 운영값을 바꾸는 테스트는 하지 않습니다. 기도 편집 작업과 별개이며 해당 기능 파일은 수정하지 않았습니다.
