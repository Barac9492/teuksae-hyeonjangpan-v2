# 메인 체육관 층별 표시 누락 보완

## 재현과 원인

2026-10-06 23:15 UTC 사용자 보고 후, 운영 `23ec71b`를 새 Chromium 문맥(서비스워커 차단)에서 읽기 전용으로 확인했다.

| 경로 | 수정 전 | 원인 |
|---|---|---|
| `/` | 체육관 1층·2층 표시됨 | 기존 `LiveWorshipStatus`는 이미 독립 ID를 사용함 |
| `/?preview=1` | 통합 `체육관 / 개방 · 여유`; 오래된 정보 모드에서는 `본당·체육관` 통합 | 별도 `PreviewWorshipStatus`에 기존 예시 행이 남아 있었음 |
| `/app` | 통합 `체육관 / 입장 가능`과 예시 확인 시각 | 구형 `TodayBeforeView`가 층별 운영 API 대신 legacy 장소 snapshot을 표시함 |

사용자가 보고한 정확한 URL은 전달되지 않았다. 일반 `/`의 미분리 현상은 새 브라우저에서 재현되지 않았지만, 위 두 실제 진입 경로의 누락은 확인했다. 서비스워커 없는 새 문맥에서도 발생해 확인된 두 누락은 캐시 문제가 아니다. 기존 서비스워커는 navigation에 network-first, API에는 캐시 미사용 정책을 적용한다. 캐시 삭제나 사용자 새로고침 안내만으로 처리하지 않고 표시 경로를 수정했다.

## 변경

- 미리보기 홈의 5개 개방 단계 및 오래된 정보 상태에 체육관 1층·2층을 각각 표시한다. 이전 단일 예시 상태를 복제하지 않고 두 층 모두 `사용률 확인 전`으로 표시한다.
- 구형 `/app` 메인 체육관 카드에는 일반 홈과 같은 읽기 전용 운영 hook/표시 함수를 사용한다. 각 층의 퍼센트·상태·확인 시각을 독립적으로 보여주고, 단일 legacy 상태 badge/가짜 확인 시각은 제거한다. 새 층 데이터가 없으면 각각 `확인 필요`다.
- `/app` 참석 장소 선택과 참석 집계는 기존 `gym` 한 항목을 유지한다. 좌석 현황을 분리하기 위해 참석 인원을 두 번 세지 않는다. 다른 장소 카드 및 기도·설교 데이터는 변경하지 않는다.
- DB·API·migration·migration-history 변경 없음. 병행 PR #43의 migration 파일명 정리는 최신 main에서 그대로 반영한다.
