# 관리자 인증과 팀 권한 (2026-09-24)

이 문서는 9월 23일의 로그인 전용 시안을 대체합니다. 현재 DB/API 계약은 [팀 운영](TEAM-OPERATIONS.md)을 함께 참고하세요.

## 권한

- **슈퍼 어드민:** 전체 주차·예배 공간 현황과 팀 계정 관리.
- **주차팀:** 송림본당 주차, 드림센터 B1~B5의 상태만 수정.
- **예배 공간팀:** 송림 학교/건물 개방 단계, 본당 1·2층, 체육관, 드림센터 3·7·11층만 수정.
- 사진 검수, 기도·나눔 접수는 여전히 연결하지 않았습니다. 기존 `/app`의 Supabase 사용자 권한을 이 로그인이 우회하지 않습니다.

## 공용 계정과 동시 입력

같은 계정으로 여러 기기에서 로그인할 수 있습니다. 각각 독립 세션이 생성되며 로그아웃은 현재 접속만 종료합니다. 비밀번호·역할·활성화 상태 변경은 해당 계정의 기존 세션을 무효화합니다.

입력 담당자 표시명은 직접 기재한 이름입니다. 공용 계정만으로 실제 개인 신원을 증명하지 않습니다. 변경 이력에는 계정, 직접 기재한 표시명, 접속별 표식, 전후 상태와 시각이 남습니다. 이 정보는 공개 현황 API에 포함되지 않습니다.

각 항목의 버전을 검사해 같은 항목의 동시 수정은 충돌로 돌려줍니다. 편집을 시작한 버전을 유지하며 자동 갱신이 임의로 버전을 올려 다른 사람의 변경을 덮어쓰지 않습니다. 최신 상태 비교 후 명시적으로 다시 저장해야 합니다. 같은 상태도 현장에서 재확인해 확인 시각을 갱신할 수 있습니다.

## 인증 경계

- 비밀번호는 salt가 있는 scrypt(N=16384, r=8, p=1) 검증값만 보관합니다.
- 계정과 역할의 최종 기준은 DB입니다. 브라우저가 보낸 역할이나 localStorage 값은 권한 근거가 아닙니다.
- HMAC 서명된 `__Host-woori_admin` 쿠키는 `HttpOnly; Secure; SameSite=Strict; Path=/`, 2시간 만료입니다. 모든 보호 API가 DB의 활성 계정·세션·자격 버전을 다시 검사합니다.
- DB에 저장되는 15분/12회 로그인 시도 예산을 사용합니다. 성공한 로그인은 자기 예약만 한 번 환불하며 다른 실패 시도를 지우지 않습니다. 재시작·다중 서버에서도 유지됩니다.
- Vercel Browser Challenge 규칙은 `^/(admin(/.*)?|api/admin/.*)$`에 적용합니다. 추가 과금형 Rate Limit 기능은 사용하지 않습니다. 보안 확인과 관리자 인증은 별개입니다.
- 보호 API와 관리자 페이지는 캐시하지 않습니다. 서비스 워커도 관리자/API 요청을 가로채지 않습니다.
- DB 장애 시 권한을 임의로 허용하지 않습니다. 공개 현황도 연결 오류·미입력·10분 경과를 이용 가능으로 표시하지 않습니다.
- 팀 계정의 새 비밀번호는 최소 4자입니다. 슈퍼 계정의 짧은 초기 비밀번호는 실제 현장 운영 전에 강한 비밀번호로 교체하는 것이 좋습니다. 팀 계정 관리 API로 슈퍼 계정을 강등하거나 비활성화할 수 없습니다.

## 배포 설정

Vercel **Production / Secret**에만 설정하며 `VITE_` 접두사를 붙이지 않습니다.

- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`: 이 앱의 전용 DB. 서버만 접근합니다.
- `ADMIN_SESSION_SECRET`: 48바이트 이상의 암호학적 난수를 base64url로 인코딩한 서명 키. 교체하면 모든 기존 쿠키를 무효화합니다.
- `ADMIN_ALLOWED_ORIGIN`: 정확한 HTTPS 앱 origin.
- `ADMIN_LOGIN_ID`, `ADMIN_PASSWORD_SCRYPT`: **최초 슈퍼 계정 생성용**입니다. DB 계정 생성 후에는 이 값이 기존 DB 비밀번호를 덮어쓰거나 대체하지 않습니다.

기존 DB에는 마이그레이션 002, 003을 순서대로 적용합니다. 공개/일반 인증 DB 역할에는 `ops_*` 테이블 및 RPC 접근을 부여하지 않습니다. API는 서버 전용 service role로 검증된 범위의 RPC만 호출합니다.

Supabase 무료 프로젝트는 장기간 사용하지 않으면 일시 중지될 수 있습니다. 행사 전 DB 상태, 실제 모바일 로그인, 저장·공개 반영을 다시 점검해야 합니다. 기능 연결은 교회 공식 승인이나 전 교인 대상 출시를 뜻하지 않습니다.
