# 우리 · 2026 특새 탭형 앱

2026-09-23 사용자 합의 기준. 최신 공개 앱은 `teuksae-hyeonjangpan.vercel.app`이다. 별도 프로젝트인 `teuksae-app` 또는 `teuksae-together`와 운영·데이터 연결을 혼동하지 않는다.

## 이번 변경

- 포스터의 흰 여백, 갈색 타이포, 흑백 왕관/손 이미지를 재사용한다.
- 루트 `/`는 예배 / 주차 / 기도 / 나눔 / 사진의 실제 탭으로 전환한다. 한 번에 하나의 화면만 표시한다. 엽서는 제거한다.
- 행사 2026-10-05~10, 04:40은 **예배 시작**이다. 학교·체육관·본당 개방 시각은 미정이다.
- 송림: 학교 밖 대기 → 학교만 개방(차량 진입과 실내 개방은 별개) → 체육관 먼저 개방 → 본당 입장 → 본당 마감. 본당 1·2층은 입장 단계만 표시하고 좌석 수/충전 게이지를 사용하지 않는다.
- 드림센터: 예배 공간 3·7·11층, 주차 B1~B5. 11층이 드물게 찬다는 사실을 현재 여유의 근거로 삼지 않는다. 만차 시 교회가 확인한 대체 장소만 안내한다.
- 간식 나눔은 송림본당만, 학교 개방 전 학교 밖 대기 장소에서 진행하는 안이다. 정확한 지점·시각은 미정이다.
- 10월 5일은 1청년부 3팀 준비. 10월 6일부터 원하는 성도들의 자율 나눔. 준비하지 않아도 참여 가능하다.
- 미개봉 티백 및 개별 포장 사탕·캔디·과자·비스킷만. 직접 만든 음식, 열린 포장, 컵에 따른 음료는 제외한다.
- 보온병 지참은 선택이다. 개인 보온병에 따뜻한 물을 준비하거나 **체육관 자체가 개방된 후** 내부 온수 정수기를 이용한다. 학교 출입문 개방만으로 정수기를 안내하지 않는다. 학교 밖에서는 온수를 배부하지 않는다.
- 마지막 정리는 사용자 표현 그대로 `교육자`가 담당하는 운영 메모로 남긴다. 일반 참가자 화면에 담당자 이름을 노출하지 않는다.
- 나눔 안의 `오늘 나눈 이야기`는 나눈 사람·받은 사람·함께 기다린 사람 모두를 위한 짧은 글 공간이다. 이름/별명은 선택이고 기본 익명. 수량·금액·좋아요·댓글·순위·인증 의무는 없다. 기도 제목과 섞지 않는다.
- 아침 식사는 공개 영업정보 기반 후보이며 영업 보증이 아니다. 송림고 인접 이른 식당은 아직 검증되지 않아 야탑 이동 후보로 명시한다. 예배 종료 시각은 임의로 정하지 않는다.

## 현재 데이터 경계

이 배포는 **승인된 디자인을 앱 코드로 옮긴 시안**이다. 교회 공식 운영 또는 성도 대상 수집 개시 승인을 대신하지 않는다.

- 장소·혼잡·주차 상태: 명확히 표시한 예시. 실시간 운영 데이터가 아니다.
- 기도: 서버 전송/저장 없는 미리보기. 공개 선택은 기본 꺼짐.
- 나눔 이야기: 현재 브라우저 세션에서만 추가/삭제/숨김을 체험한다. 다른 사람에게 공개되지 않고 신고도 서버로 접수되지 않는다.
- 사진: JPG/PNG/WebP 8MB 이하 로컬 미리보기. 파일 업로드나 서버 저장을 하지 않는다. 객체 URL은 정리한다.
- 실제 공지, 푸시, 메시지 발송 없음. 유료 리소스 생성/연결 없음.
- 기존 `/app` 운영 리허설과 Supabase 계약은 보존하지만 새 루트 화면과 자동 연결하지 않는다. 기존 `officialApproved=false` 승인을 변경하지 않는다.

## 사진 백엔드 권장안

**Vercel(웹 호스팅) + Supabase(비공개 Storage와 메타데이터 DB)**를 우선 권장한다. 코드에 이미 `SupabaseGateway`, 비공개 `moment-submissions`, 동의된 제출 메타데이터, 운영자 검수 RPC가 있다. 환경변수 이름이 등록돼 있다는 것만으로 현재 연결/스키마/정책이 검증됐다고 판단하지 않는다.

계정에는 과거 별도 특새 프로젝트의 Blob/DB도 존재하지만, 같은 이름 계열이라는 이유로 연결하거나 기존 데이터/권한을 바꾸지 않는다. 재사용 여부는 소유 프로젝트·접근정책·기존 데이터 영향 확인 후 결정한다.

### 사진 파일과 DB의 역할

사진 파일은 object storage에 두고 DB에는 파일 경로, 익명 업로더 세션, 동의 버전, 접수 시각, pending/approved/rejected 상태, 검수 담당·시각, 삭제 시각만 둔다. 원본은 비공개이며 대량 공개 URL을 만들지 않는다. 서비스 역할 키는 브라우저에 넣지 않는다.

### 실제 수집 활성화 전 필수 작업

1. 프로젝트 연결과 비공개 버킷/RLS를 독립 검증한다. 다른 사용자의 원본·대기 사진에 접근할 수 없어야 한다.
2. 사용자 인증 또는 익명 인증, 업로드 용량/MIME/디코딩 검증, 요청 제한을 서버 측에서 강제한다. 공개 URL만 알면 무제한 업로드되는 형태는 금지한다.
3. 원본 업로드는 브라우저에서 비공개 버킷으로 직접 전송한다. Vercel Function을 8MB 파일 중계 경로로 사용하지 않는다.
4. 사진을 실제로 디코딩·재인코딩하고 EXIF/GPS를 제거하는 서버 처리를 추가한다. 현 코드의 원본 업로드/검수 RPC만으로 안전한 공개 파이프라인이 완성된 것은 아니다.
5. pending 사진은 공개 목록에 절대 나오지 않는다. 운영자 승인과 안전 처리 완료를 모두 충족한 파생본만 갤러리에 제공한다. 인증/서명 URL·캐시 정책을 함께 검증한다.
6. 촬영된 사람과 미성년자 보호자 동의, 실제 열람자, 삭제 요청 창구, 행사 후 보관/삭제일을 확정하고 참가자에게 안내한다.
7. 개인 원본·메타데이터·공개 파생본·DB를 함께 삭제할 수 있게 한다. 삭제/차단 회귀 검사를 포함한다.

기도 제목은 사진보다 민감할 수 있다. 기도 접수는 담당자 범위·보관 기간·삭제 절차·공개 동의가 정해지기 전 활성화하지 않는다.

### Google Photos를 기본 저장소로 쓰지 않는 이유

공유 앨범 링크는 전달될 수 있고, 공동 추가를 켠 앨범은 앱의 게시 전 승인 큐를 대체하지 못한다. 작은 동의된 그룹의 수동 앨범 링크로는 쓸 수 있으나, 공개 교회 앱의 검수형 사진 저장소로는 부적합하다. 2025-03-31 이후 Google Photos Library API의 공유 기능과 광범위 라이브러리 범위가 축소돼 기존 공유 앨범을 자유롭게 앱 백엔드처럼 다루는 설계도 피한다.
